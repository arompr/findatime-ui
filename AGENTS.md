# AGENTS.md

## What this application is

**findatime-ui** is the frontend for the Findatime event-scheduling product
(see `findatime-api`). Two pages:

- **Homepage (`/`)** — join an event by public code (name + passcode when
  protected), create an event, and list the guest's events.
- **Event page (`/events/$publicId`)** — inline join for guests without a
  participant, then the availability calendar: mark/edit your own availability
  (tap/click, drag-create, move/resize blocks), see everyone's overlap as a
  heat map, share the link, leave the event. Organizers additionally get event
  settings (event timezone, slot interval, calendar hours) and event deletion.

On desktop, month view is a day-level overview: each day is shaded by its peak
overlap with a "best window" chip. In edit mode, clicking a day (or dragging
across several) opens `DayAvailabilityForm` through ilamy's event-form hook
(`renderEventForm` / `openEventForm`), which replaces those days' ranges.

The UI is mobile-first: below the `sm` breakpoint the calendar opens on a
single day (swipe or arrows to change days) with a Day / Week / Month switch;
swipe moves by the current view's period, month chips shrink to a start time or
overlap count, and tapping a month day opens that day rather than its week.
Block interactions use press-and-hold drag; hover affordances stay visible on
touch devices.

## Tech stack

- **Vite + React 19 + TypeScript** (SPA).
- **TanStack Router** (file-based routing with code-generated route tree).
- **TanStack Query** for server state / mutations.
- **Tailwind CSS v4** for styling.
- **@ilamy/calendar** for the calendar grid (with custom plugins).
- API calls via `@arompr/findatime-typescript-client` (GitHub Packages,
  generated with hey-api).

## Smart/dumb architecture

- **Smart** components (`HomePage.tsx`, `EventPage.tsx`,
  `AvailabilityCalendar.tsx`) own hooks, state, and API access; they pass data
  and callbacks down as props.
- **Dumb** components (`components/**`) are purely presentational: props in,
  events out. No API imports, no query hooks (local input state and
  presentation hooks like `useIsMobile` are fine).

## API access

All API calls go through `src/lib/api.ts`, which configures the hey-api
`client` (baseUrl from `VITE_API_URL`, default `http://localhost:5263`) and
exposes one function per endpoint. Identity is a guest token from
`guestToken.ts`: the client's `auth` callback sends `Authorization: Guest <token>`
on the operations the OpenAPI document marks as secured, issuing the token on
first use. The guest is never named in bodies or URLs. A 401 drops the token
and retries once with a fresh one.
The client returns `{ data, error, response }` envelopes; `unwrap` turns
failures into `ApiRequestError` (status + API error code) so TanStack Query
`isError` and `messageFor` (in `errors.ts`) drive the UI. Endpoints take the
public id directly.

Availability is exchanged as UTC instants; the server snaps to the event's slot
grid in the event timezone. The browser converts only for display. Inside the
app, ranges are UTC ISO strings (`startUtc`/`endUtc`, normalized to `...Z` when
read so keys stay stable) and are sent back as-is. The participant's timezone is
sent once, on join.

## Conventions

- 2-space indentation, double quotes, semicolons (see `.editorconfig`).
- Path alias `@/` maps to `src/`.
- Use named exports for components and functions.
- Tailwind utility classes only; keep styling sober and minimal. Use the semantic
  theme tokens from `index.css` (`bg-card`, `text-muted-foreground`, `border-border`,
  `bg-brand`, …), never raw palette colors, so light and dark themes both work.
- Buttons: `primary` (solid ink) for the one main action in a view; every other
  text button is `secondary` (hairline outline that lifts on hover); `ghost` only
  for icon-only buttons. Custom tiles reuse `buttonVariants` from `Button.tsx`
  instead of hand-rolled styles. View toggles and filters that sit among data
  (e.g. "Find a time") are pill chips, solid ink when on, not buttons.
- Copy is for non-technical guests: say what something does for them, not how
  it works (no "grid", "snaps", "slot length").
- Mobile-first: design for <640px first, extend with `sm:` variants; touch
  targets >= 40px; don't rely on hover (use `[@media(hover:none)]:` fallbacks).
- No comments unless they clarify non-obvious behavior.

## Commands

```bash
npm install          # requires a GitHub token in ~/.npmrc (see README) for the typescript client
npm run dev          # dev server on :5173
npm run build        # route generation + typecheck + production build
npm run lint         # typecheck only

make container       # build the Podman image (mounts ~/.npmrc as a secret)
make container-dev   # run the image at :8080 (API calls go browser -> :5263)
```

The API expects the dev server origin (`http://localhost:5173`) in its
`Cors:AllowedOrigins`.
